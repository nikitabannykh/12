# Как робот готовит объявления

Принцип — как у директолога: **сначала запрос, потом объявление, потом картинка под это объявление**. Каждый шаг проверяется, и владелец видит только то, что прошло проверки.

## 1. Тип бизнеса

`isOrderBusiness` (engine/extras.ts) по названию, описанию, общим запросам и позициям прайса различает:

| Тип | Примеры | Призыв | Подписи |
|---|---|---|---|
| **Заказ** | доставка еды, кафе, кондитерская | «Закажите онлайн» | «Меню и цены», «Заказать онлайн» |
| **Запись** | салон, массаж, остеопат, студия | «Запишитесь онлайн» | «Цены на услуги», «Записаться онлайн» |

В объявлениях для «заказа» слов «запись», «записаться», «удобное время» быть не может: это проверяется кодом.

## 2. Группы поиска — от запроса

**Запись (услуги)** — `buildSemanticCore`:
- общая группа — как ищут сам бизнес («детский остеопат»), из `searchTopics` (YandexGPT по анкете);
- группы услуг из прайса, слои «проблемы клиентов», «смежные запросы», «аудитории».

**Заказ (каталог)** — `catalogCore` + engine/catalog.ts:
- разделы меню по словарю («Пицца», «Роллы», «Сеты», «Вок и поке», «Десерты»…). Позиции попадают в раздел по названию и разделу с сайта;
- запросы раздела: «доставка пиццы», «заказать пиццу», «пицца на дом», с городом, «недорого», «меню»; названия позиций — длинный хвост;
- общая группа («доставка еды») собирается после разделов, поэтому «доставка пиццы» достаётся разделу «Пицца»;
- кросс-минусовка: «Пицца» не показывается по «роллам», и наоборот;
- напитки рекламой не продаются — спроса «с доставкой» на них нет;
- позиция меню отдельной группой не становится: у «Панна-котты Привидение» ноль запросов в месяц.

## 2а. Проверка фраз директологом

Перед текстами готовые фразы каждой группы проверяются (`reviewKeywords`, engine/kwreview.ts):
- **код:** убираются обрывки из прайса («остеопат лет старше» из «от 14 лет и старше») и чужая аудитория («для взрослых» в детской группе);
- **YandexGPT по каждой группе:** имена врачей и мастеров, чужие клиники и бренды, другой город, справочные запросы («парацетамол от головной боли»), услуги, которых нет, фразы другой группы. Найденные имена и бренды становятся минус-словами кампании.

- **группы проблем:** только фразы с намерением обратиться («остеопат при боли в спине», «болит спина лечение», «… к кому обратиться», с городом). Голое «болит спина» — справочный запрос, его не берём;
- **название группы** — как ищут люди: «Взрослый вторичный прием остеопата» → «Остеопат для взрослых». Связь с позицией прайса (`service`) остаётся.

В группе всегда остаётся не меньше 2 фраз. Сколько убрано и примеры — в `checks.review` ядра.

## 3. Тексты — три шага

1. **Автор** (YandexGPT, отдельный запрос на каждую группу, параллельно по 4). Получает анкету, тип бизнеса, запросы группы и позиции раздела с ценами. Пишет 4 объявления с разными подходами: цена, предложение, доказательство, удобство, результат.
2. **Старший директолог** (YandexGPT, `reviewAds`). Проверяет каждое объявление по чек-листу и правит:
   - заголовок отвечает на первый запрос группы;
   - нет товаров и услуг не из этой группы;
   - только факты из анкеты;
   - призыв по типу бизнеса;
   - без штампов, восклицаний в заголовке, «лучший», капслока;
   - в лимитах длины, объявления не повторяют друг друга.
3. **Жёсткие проверки кода** (`gateAd`, `factCheckAd`). Их модель не может «уговорить»:
   - в заголовке есть слово из названия группы или её запросов;
   - нет «записи» у бизнеса с заказом;
   - нет «!» в заголовке;
   - длины в лимитах;
   - факты (цены, сроки, обещания) есть в анкете.

   Не прошло — объявление заменяется шаблонным для этой же группы. Шаблон тоже собран из фактов анкеты и позиций этого раздела.

## 4. Расширения под объявление

- **Быстрые ссылки и «Меню и цены»** (`adExtras`). Позиции прайса ранжируются по близости к запросам группы: к «доставке пиццы» — пиццы, без десертов. Если есть позиции про запрос, ссылки только на них.
- **Уточнения** — факты анкеты, «Заказ онлайн» или «Онлайн-запись» по типу бизнеса.

## 5. Картинки

**У каждой группы своя картинка.** Сюжет придумывается под каждую группу поиска по её названию («Пицца», «Боль в шее»), затем под группы РСЯ и VK — до 20 кадров. Чужой кадр группе не ставится: если её кадр не получился, у неё карточка с её же подписью.

Порядок выбора для каждой группы:

1. **Своё фото этой позиции или раздела.** При чтении сайта сохраняется подпись фото: alt картинки или позиция меню из встроенного JSON. «Сет Свежесть» получает фото «Сета Свежесть», раздел «Пицца» — фото любой пиццы с сайта.
2. **Сгенерированное фото под группу.** YandexGPT придумывает сюжет под запрос группы и её главные фразы («ищут: …»): «доставка пиццы» — пицца в коробке у двери, а не десерт. Рисует Alice AI ART (Images API, модель `YANDEX_IMAGE_MODEL`, по умолчанию `aliceai-image-art-3.0`) по 3 одновременно, с повтором при сбое. Если генератор отказался рисовать сюжет (дети, тело), — повтор с нейтральным кадром ниши без людей. Кадры рисуются шагами: картинки объявлений собираются, только когда у каждой группы есть свой кадр. Одно своё фото двум группам не ставится.
3. **Типографская карточка без рисунка**, если не вышло ни то, ни другое. У «Другой услуги» общая иллюстрация записи (галочка с часами) больше не рисуется.

Правила кадра, которых держимся:
- в кадре ровно то, что ищут: пицца для «пиццы», ролл для «роллов»;
- товар крупным планом, один главный объект, без мелкого текста;
- свои настоящие фото важнее сгенерированных;
- подпись на картинке короткая: так клиент называет услугу, а не как она записана в прайсе;
- адрес с номером дома;
- у каждой группы поиска два кадра с разными сюжетами (процесс и результат, общий план и деталь): объявления группы чередуют их, робот A/B-тестом оставляет кадр, после которого чаще заказывают или записываются.

## Где в коде

| Что | Файл |
|---|---|
| Тип бизнеса, расширения | `src/lib/engine/extras.ts` |
| Разделы меню | `src/lib/engine/catalog.ts` |
| Группы и запросы | `src/lib/engine/semantics.ts` (`buildSemanticCore`, `catalogCore`) |
| Тексты, проверка, шаблоны | `src/lib/ai/copy.ts` (`generateCopyPlan`, `reviewAds`, `gateAd`, `templateAds`) |
| Сюжеты и генерация картинок | `src/lib/engine/images.ts` (`serviceArt`, `generateServicePhotos`) |
| Выбор картинки под группу | `src/lib/engine/launch.ts` (`prepareImages`) |
| Макеты картинок | `src/lib/creative/render.tsx` |
